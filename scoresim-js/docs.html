ScoreSim (Vanilla JS) — Documentation

A dependency-free browser port of the Angular/TypeScript "Football Results Simulator". Open index.html directly (double-click) — no server, build step, or install needed.

File structure

index.html      UI markup (settings form + scoreboard + stats)
style.css       Styling
docs.html       This page
data/clubs.js   UEFA club database   (const UEFA_CLUBS = [...])
data/nations.js UEFA nations database (const UEFA_NATIONS = [...])
js/strength.js  Team strength derivation (pure functions)
js/engine.js    Match simulation engine (pure, UI-free)
js/ui.js        DOM wiring, timer, rendering
img/            Fallback team logo

Data is embedded as .js files instead of JSON so the app works from file:// without CORS/fetch issues.

Architecture

ui.js reads the form and builds a MatchConfig; engine.js owns all simulation state and exposes kickOff(), tick() (advance one match minute) and simulateToEnd(). The UI calls tick() every 150 ms and re-renders. The engine never touches the DOM and accepts an injectable RNG, so it is directly unit-testable in Node (module.exports guard at the bottom of each js file).

Strength derivation (strength.js)

If both teams exist in the database, a recommended strength bucket is computed: clubs — compare last-season division (each division apart shifts 1–2 buckets), else points ratio thresholds (0.8 / 0.8889 / 0.9412 / 1.0625 / 1.125 / 1.25); nations — FIFA ranking difference buckets (±5 → equal, ±10, ±30, beyond). Buckets map to 30/70, 40/60, 45/55, 50/50, 55/45, 60/40, 70/30. The user can override.

Simulation model (engine.js)

Pre-match

  • allPotentialFouls = 20 + rand*7, split inversely by opponent strength.
  • allPotentialShots = 24 × (home tactics + away tactics) / 2. Continuous and symmetric; 24 shots at balanced tactics.
  • Each side's shot share is strength / 100 applied to the square root scale: shares are √s / (√s_home + √s_away), which softens the gap between teams.
  • Per-match shot accuracy constant per team: uniform 0.1–0.5 (not scaled by strength; lever 1 is off).

Each simulated minute (tick)

  1. Possession: weighted coin flip on strength (± a noise adjuster that narrows big mismatches) moves possession 0–1 point, clamped to 15–85. The winner gains a tiny morale edge.
  2. Fouls (each side): probability potentialFouls/90. On a foul: 1/7 chance of a yellow to a random player (second yellow ⇒ red, player removed, strength −9%, morale ±15% coin flip); otherwise 1/500 chance of a straight red.
  3. Shots (each side, independently): probability potentialShots/90 × possessionModifier, where possessionModifier = log(possession) / log(50) (natural log, 50% possession = 1.0x, range ~0.69–1.14x). On-target per the accuracy constant (+0.2 morale); goal chance is max(0.20, (conv(strength)+morale[+crowd])/100 / (1.4+rand)), where conv(s) = 50·(s/50)^p with p = 1 (linear). The 0.20 floor applies to both sides equally. Scorer is a random outfield player; +1 morale on scoring.
  4. Clock: injury time 0–5 min rolled at 44' and 89'; 5-tick half-time break; at FT, two-leg ties level on aggregate go to extra time, then a penalty shootout (random 0–5 each, sudden death until decided).

Bug fixes vs. the original Angular app

Away shot suppression: the away team could only shoot in minutes when the home team didn't (hidden else nesting). Both sides now roll independently.
Wrong yellow-card counter: an away second yellow pushed the home yellow count to the UI. Counters now always track the correct side.
Biased / out-of-bounds player pick: Math.round(0.5 + rand*(len-1)) could produce index = length (undefined ⇒ crash) and was non-uniform. Replaced with Math.floor(rand*len); goalscorers are now outfield players only.
Asymmetric red-card morale: away teams suffered −25%/+5% where home had ±15%. Now symmetric for both sides.
Never-cleared interval: the original setInterval ran forever after full time. The UI timer is cleared when state.isFinished is set.
Dead aggregate logic: an always-true condition (a==b || a>b || a<b) wrapped the extra-time branch; removed.
Empty-lineup crashes: fouls/shots are skipped if a side has no players left (pathological red-card scenarios).

Using the engine programmatically

const engine = createMatchEngine({
  homeStrength: 60, awayStrength: 40,
  homeCrowdSupport: 5, homeMorale: 3, awayMorale: 2,
  homeTactics: 1.2, awayTactics: 0.8,
}, mySeededRng);           // rng optional; defaults to Math.random

engine.simulateToEnd();     // or: engine.kickOff(); engine.tick(); ...
console.log(engine.state.homeGoals, engine.state.awayGoals);
console.log(engine.state.homeGoalEvents);  // [{name, minute}, ...]

In Node: const { createMatchEngine } = require('./js/engine.js'); — this is the hook for the unit tests we'll add next.

Known limitations / enhancement ideas

  • Substitutes exist in neither data nor engine (the original had unused sub arrays).
  • No away-goals rule (matches current UEFA rules; trivial to add as a config flag).
  • Penalty shootout is purely random, not kick-by-kick.
  • Morale is unbounded upward; a clamp (e.g. 0–10) is a good balance tweak.
  • Possession currently moves at most 1%/minute; a float accumulator would be smoother.
